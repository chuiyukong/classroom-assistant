# 未来开发计划（未开工）

更新：2026-09-06。以下全部为建议与需求记录，**本次不实现**。当前先稳定座位登记 1.1.0。推荐顺序：机房验收 → 随机点名 → 考勤 → 噪声检测 → 互动挑战。

## 共用基础

后续模块读取 `get_current_arrangement()` 获取当前上课班级、登记 id、学生 id、座位和分组。事件开始时保存名单快照；过程中更换座位安排不得静默改变已发起的考勤、点名或游戏。各功能有自己的事件编号、结果表和历史，不写回座位登记表。

正式考勤前优先补充学号/班级名单导入和教师确认的身份关联。IP 只作为设备线索；不把换 IP、共享 IP 或同名自动认定为某位学生。

## 1. 随机点名（优先，工作量相对小）

- 使用当前座位名单；可选全班、某小组、已签到学生；教师排除请假人员。仅备注不自动排除，避免误判。
- 姓名滚动、座位高亮动画、最终大字显示；增加“减少动画”模式。随机结果先由服务端生成，动画仅展示，不用帧率或点击时刻决定概率。
- 可选抽一次不重复、每人公平轮换、指定人数；保留抽取日志与本节课重置入口。教师排除名单在开始前可查看。
- 验收：重名学生可独立被抽到；名单为空/只有一人/全部排除时提示；刷新页面不重抽；重复请求返回同一结果。

## 2. 考勤签到（优先，工作量中等）

- 教师从当前安排发起本节课考勤。学生输入姓名，系统核对座位名单；重名到教师端处理。签到页沿用现有学生网址。
- 本次考勤独立限流：每个学生 id 和每台设备只能完成一次本次签到；不被之前的座位登记 IP 限制挡住。
- 教师设置开始时间、准时截止/宽限和结束时间。以服务器收到首次有效签到的时间计算迟到分钟数，重复提交不刷新首次时间。
- 状态建议：未签到、已到、迟到、请假、缺席、教师补签。开放期间显示未签到；结束时才按规则确认缺席，避免刚开始就判缺席。
- 教师可修正状态并记录原因；长期请假/休学备注给教师参考，后续可增加明确的免签到状态及生效日期，不能靠关键词自动处理。
- 换座需要教师确认，避免学生在其他电脑代签；先支持“来源 IP 与已知座位不一致时提示”，可靠的固定机号绑定要独立设计。
- 验收：换班/下节课可立即签到；服务重启不丢失首次签到时间；延迟请求不能写入上一节课；已有考勤使用原名单快照。

## 3. 教室噪声提示（中优先，需要实机麦克风验证）

- 使用教师机上实际带麦克风的耳机或独立麦克风；只有播放功能的耳机无法采集。先提供设备选择、输入电平测试、安静基线校准和手动开始/停止。
- 建议先在教师本机浏览器通过 getUserMedia + Web Audio 分析振幅，无需在 Win7 学生机采音。教师页的 localhost 地址满足浏览器本地可信来源条件；需要明确授权麦克风。[MDN 安全上下文](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)、[getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)
- 用短窗 RMS、平滑电平和持续超阈时间触发，避免一次咳嗽就报警。普通麦克风未校准时显示“相对音量”或 dBFS，不宣称测得准确的环境声压级 dB SPL。[MDN 时域音频数据](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData)
- 教师可选界面警示、短提示音或两者；建议持续 2—3 秒超阈才提醒，冷却 15—30 秒，可暂停讲课/播放视频期间提醒。具体默认值需实机试测后确定。
- 提示音播放期间暂停判定，避免自己的声音反复触发。根据教师讲解/小组讨论设置不同阈值，而不是全课要求一个阈值。
- 默认只在内存处理电平，不保存原始录音、不识别说话人、不上传音频。需要历史时只保存时间与电平统计。
- 验收：不同麦克风增益、无设备/被占用/拒绝权限、拔插、静音、提示音回灌、浏览器后台降频。噪声电平不能识别是教师讲课还是学生讲话。

## 4. 互动小游戏 / 课堂挑战（中后期）

建议定位为短时“课堂挑战”，可用于提神或纪律提醒后的复盘。提供跳过/替代题、不公开羞辱和不限体力的设计；不将高难游戏输赢直接计入惩罚分。

| 候选 | 玩法与难度 | 教学结合 |
|---|---|---|
| 算法迷宫 | 用有限指令走出迷宫；提高版限制步数或加入循环 | 顺序、分支、循环 |
| 二进制解码 | 30—60 秒将数字/颜色编码还原；分多档 | 信息编码 |
| 找 Bug 接力 | 找出短程序中的逻辑错误，先解释再运行 | 调试和表达 |
| Stroop 颜色挑战 | 按文字颜色而非字义作答；可放慢或换非色觉题 | 注意力切换 |
| 逻辑锁与数独片段 | 小规模逻辑推断，多步条件逐渐增加 | 推理与策略 |
| 小组协作拼图 | 每台机只有部分线索，口头协作完成 | 合作与信息整合 |

默认每局 1—3 分钟、教师一键结束、可调难度和减少动画/静音。服务器保存结果，客户端不自行提交可信得分；失败、断线和重复提交有明确处理。小游戏框架不应耦合考勤或座位写入。

## 5. 其他值得考虑的功能

| 建议 | 具体用途 | 建议优先级 |
|---|---|---|
| 学生举手 / 求助队列 | 点击座位发出求助，教师按等待时间处理，不必满教室喊老师 | 高 |
| 课堂计时与阶段提醒 | 操作练习、讨论、展示共用倒计时，教师暂停或延长 | 高 |
| 一题快答 / 理解度投票 | 学生选“会了/需要帮助”或答一题，教师在座位图看分布 | 高 |
| 离堂反馈 | 下课前一句收获、一个问题，保留到班级教学记录 | 中 |
| 设备报修闭环 | 学生报告故障，教师确认后变停用，记录维修与恢复时间 | 中 |
| 分组与角色轮换 | 按既有小组分配组长、记录员、汇报人，避免总由同一人承担 | 中 |
| 任务完成进度 | 学生报告进度卡点，教师快速定位需要支持的座位 | 中 |
| 课堂资源入口 | 集中展示本课链接、材料和提交地址，减少手输网址 | 中 |
| 班级课后概览 | 汇总签到、帮助请求、任务完成和反馈，避免只用纪律数据评价学生 | 后期 |

极域已有广播、远程控制、文件分发功能，暂不重复开发这些重型能力。先围绕座位名单提供轻量辅助。

## 新功能开工前确认

每个模块先写清：课堂触发方式、使用者、数据归属、是否显示学生姓名、完成与取消行为、重复请求和断线行为、实际机房验收方法。经用户明确选择后再安排版本，不按本文自动开工。
