# AI 课堂对话采集：待开发方案

更新：2026-09-07。1.2.0 未实现 AI 对话，也未调用任何付费 API。用户提出的“简单则一起开发”经评估不能简化为直接转发：全班并发、费用、流式重连与身份隔离需要独立实现和验收。下一阶段优先开发此模块。

## 可行性与范围

同一教师账号的 API 可以供多台学生机使用。学生机请求教师机，由教师机使用密钥调用 DeepSeek；密钥永远不发给学生，不写入网页、日志、GitHub 或下载包。并发限制按账号计算，多个 Key 不会增加账号总额度。官方当前文档列出的并发能力可以覆盖 64 台机器，但实际速度仍取决于模型、账号配额、负载和网络；不能承诺 64 人同时满速生成。

依据：[DeepSeek 限速与隔离](https://api-docs.deepseek.com/quick_start/rate_limit)、[模型与价格](https://api-docs.deepseek.com/quick_start/pricing)。开工时再次核对模型、价格和并发说明，不将今天的数值固化进程序。

采集范围仅限学生在本平台发送的提示词与收到的 AI 回复。无法采集他们另开网页、其他应用中的对话。无需监控屏幕或读取其他浏览器数据。

## 学生与教师流程

1. 教师开始本节课，开启“AI 学习”，设置任务名称、模型、每人请求次数、输入长度、最大输出长度和本节总预算。教师在本机设置页填写 Key，默认禁用，测试成功后显式开放。
2. 学生完成本节签到，以服务端签到身份关联课堂、学生编号和实际座位。重名由教师处理，不能仅依赖自填姓名。身份绑定不是实名认证，仍需要教师现场核对。
3. 页面明确说明：在此页面提交的提示词和 AI 回复会保存供教师教学分析；提示词将发送给 DeepSeek，请勿填写私密信息。发送给供应商的身份字段使用随机编号，不附带真实姓名、班级、请假备注。
4. 学生输入提示词，显示排队、生成中、完成、失败状态。回复逐步出现，可停止。断线后凭服务端生成任务编号重新获取已生成内容，不重新调用模型、不重复收费。
5. 教师按课堂、学生、座位查看对话、请求次数、输入输出字数和 Token 用量；可按日期查询并导出。首版只做客观统计，不自动判断学生能力、不自动给纪律分。
6. 教师结束任务后禁止新请求；在途任务可停止或有界完成。定义保留期限和按课堂删除记录的操作，删除前清晰显示范围。

## 技术组织

- `ai_learning` 模块保存任务、会话、消息与用量，读取课堂/考勤公共接口；不读取或修改座位内部表。
- 教师机单独的有界工作队列调用 DeepSeek SSE 流。首版建议默认 8 个工作请求、64 个排队位置，教师按实测调整；一个学生最多一个在途请求。禁止让几十条供应商长连接占住 Waitress 所有网页线程。
- 学生端保留 ES5 与 XHR。优先使用短轮询读取增量文本（约 300—500ms，可调），实现逐步显示；服务端对供应商使用真正的流式请求。若改用浏览器 SSE，必须验证旧版 Chrome/Firefox、断线重连及每浏览器连接上限。
- 增量按批次持久化，避免每个字都写 SQLite；读取游标只能访问自己的任务。断线不重新触发生成；程序重启将未完成任务标为“中断”，保留已有文本，不自动重放付费请求。
- 处理 401、429、余额不足、超时、断流、空增量和 SSE keep-alive。已开始输出的任务不自动重试；未开始输出的限流只允许有限退避，防止放大请求或重复计费。
- 预算按输入估算和最大输出预留，再用供应商返回用量结算；费用估算需标注价格版本，余额不足立即停止新任务。提供每生与全班总量双重限制。
- API Key 使用 Windows 用户范围的安全存储或 DPAPI；配置接口只返回“已设置”，不返回原文。导出排除密钥和内部错误响应。
- 教师查看任意对话仍沿用本机、管理会话、同源和 CSRF 校验；学生查询强制验证签名会话和任务归属。

## 建议数据库与接口

独立表：ai_activities（课堂任务/限制快照）、ai_conversations（学生关联）、ai_jobs（幂等键/排队/运行状态）、ai_messages（角色/文本）、ai_usage（模型/Token/费用估计）。新增迁移，升级前备份。

学生：创建消息任务、查询自身任务增量、停止自身任务、读取自身会话。教师：设置密钥、开启/结束活动、查看汇总、查询/导出/删除课堂对话。供应商响应中的文本按纯文本渲染，不能执行 HTML；如加入 Markdown，必须使用本地打包且经过审查的净化库。

## 交付前验收

模拟 64 人同时提交、排队公平性、教师操作仍能及时响应、学生之间无法读取对话、断线续显、超时/429、密钥不出现在日志或前端、单生和全班预算、停止/结束课堂、重启恢复、中文流式边界。供应商集成先用假流服务测试，再使用教师提供的 Key 做小额实测，最后在机房验证；未实测前不能宣传全班稳定可用。
